# Count-semantics failure-routing study — methods and results record

## Scientific question

Can source-grounded, risk-ranked review distinguish true extraction count
errors from reference-answer errors without erasing predictions or optimizing
the answer key toward the model output?

This record freezes the study design and interpretation used on 2026-08-10. It
is a dated benchmark record, not the live production headline; current headline
metrics remain in `docs/RECALL_STATUS.md`.

## Evaluation cohort and reference standards

- **Papers:** 56 total: the locked 48-paper cardiac high-carrier evaluation set
  plus all 8 BRCA2 papers in the curated extraction benchmark.
- **Genes:** KCNH2, KCNQ1, SCN5A, RYR2, and BRCA2.
- **Reference standard:** manual gold for the four cardiac genes;
  curator/LLM-derived `gold_overrides` for BRCA2. BRCA2 results are therefore
  reported separately and are provisional.
- **Predictions:** existing A1 production predictions. Cardiac and BRCA2
  prediction JSON files were SHA-256 locked before any count adjudication. Their
  digests are recorded in `runs/20260810_luna_xhigh_56/metrics.json`.
- **Unit of carrier-error analysis:** a gold carrier assertion for which the
  locked predictions supplied a carrier count. There were 378 such observations
  both before and after adjudication.

## Prospective count-scope policy

The focal count was defined before reviewing individual disagreements:

1. Count focal-variant carriers in the current paper's study or analysis
   cohort, not recruitment totals, prior cohorts, unpublished observations,
   relatives without the variant, or allele copies.
2. For treatment/effect studies, use the enrolled analysis cohort. For
   population genotyping studies, use all focal genotyped carriers.
3. Record affected/unaffected partitions only for the explicitly assessed
   subset; partitions need not sum to the carrier total.
4. Use null when phenotype was not systematically ascertained. Do not infer
   zero or calculate `carriers - affected` without direct source support.
5. Exclude duplicate answer-key rows describing the same current cohort.

## Intervention sequence

1. **Lock predictions.** The cardiac and BRCA2 prediction files were hashed and
   held unchanged so adjudication could not masquerade as re-extraction.
2. **Locate influential disagreements.** Count-bearing rows were ranked using
   source layer, large counts, arithmetic mismatch, repeated count tuples,
   missing/non-per-variant provenance, and scanner/regex origin.
3. **Build compact evidence cards.** Each card contained the target gene,
   variant, extracted values, title/PMID, and a bounded source excerpt centered
   on notation aliases. Prefixless, one-letter, three-letter, and stop-codon
   protein aliases were bridged.
4. **Source-grounded review.** Seven selected cards were reviewed with
   `azure_ai/gpt-5.6-luna` at xhigh. GPT-5.6 xhigh alone received a 64k output
   allowance because hidden reasoning otherwise exhausted the response budget
   before JSON emission.
5. **Fail-closed reference loading.** `utils/gold_standard.py` centralized the
   `gold_v2` status vocabulary for both scorers and the claim pilot. Unknown
   states raise an error; populated v2 status makes all v2 count fields
   authoritative, including explicit nulls; duplicate/background states are
   excluded consistently.
6. **Prediction-blind independent audit.** Fifteen randomized source-only cards
   were reviewed separately by Grok 4.5 High, Gemini 3.1 Pro High, and Claude
   Fable 5 Max. Reviewers did not receive predictions, legacy gold, v2 gold,
   error direction, or one another's answers.

## Metrics

For count field `f`, conditional mean absolute error was calculated over the
`N_f` reference assertions with a supplied locked prediction:

`MAE_f = (1 / N_f) * sum_i |prediction_i,f - reference_i,f|`

Count recall was:

`count recall_f = supplied predictions_f / eligible reference assertions_f`

MAE and recall are reported together because deleting difficult predictions can
improve conditional MAE while reducing coverage.

## Results

| Field | Before absolute error / MAE | After absolute error / MAE | Count recall after |
| --- | ---: | ---: | ---: |
| Carriers | 308 / 0.8148 | **30 / 0.0794** | 378/1110 (34.05%) |
| Affected | **240 / 0.7869** | 241 / 0.7902 | 305/1109 (27.50%) |
| Unaffected | 51 / 0.1802 | **37 / 0.1307** | 283/1108 (25.54%) |

Carrier absolute error fell 90.3%, but **no extraction prediction changed**.
The carrier-recall denominator decreased by one because a duplicate gold row
was excluded. The result therefore demonstrates that count-scope definitions
and scorer behavior dominated the apparent carrier error on this selected set;
it does not demonstrate a 90.3% extraction improvement.

Carrier results by reference-standard stratum:

| --- | ---: | ---: | ---: |
| Cardiac 48, manual gold | 326 | 16 | 0.0491 |
| BRCA2 8, provisional curated gold | 52 | 14 | 0.2692 |
| Combined 56 | 378 | 30 | 0.0794 |

## Robustness and negative controls

- All three independent reviewers agreed on the carrier totals for the five
  headline cards and six corrected controls.
- Two controls retained reference carrier count 3 even though the locked
  prediction was 2. This moved neither answer toward the prediction.
- Correcting RYR2 R420Q to include a symptomatic carrier increased affected
  absolute error by one. The regression was retained because it was
  source-supported.
- Two cards lacked decisive source evidence and were left unchanged.
- Phenotype partitions showed more reviewer disagreement than carrier totals;
  only explicitly reported phenotype definitions were retained.

## What worked and what did not

**Worked:** compact, notation-aware source cards; explicit current-cohort
definitions; field-wise fail-closed corrections; one shared v2 loader; blinded
multi-model review; and negative controls that could move against predictions.

**Did not work:** broad missing-slot recovery. Six attempted Luna calls consumed
153,010 tokens and completed 162 gap checks with zero grounded additions. The
route was stopped and remains default off. Two blind cards omitted decisive
source evidence, and seven additional variants in RYR2 PMID 33606749 remain
outside the blind audit.

## Runtime and production status

- The production A1 trace comprised 16 Kimi table-routing calls, 55 Grok 4.3
  extraction calls, 90 GPT-5.6 Sol figure-reading calls, and 142 GPT-5.6 Sol
  risk-ranked claim-verification calls across the 56 papers.
- The seven compact Luna shadow calls used 17,901 input and 9,781 output tokens
  (27,682 total) in 80.9 seconds.
- Commit `4a23b42` is contained by `origin/main`. It supplies risk ranking,
  compact verification, fail-closed v2 loading, evidence routing, and tests.
- Current local production configuration enables Tier-3 ensemble QA with Grok
  4.3 extraction and GPT-5.6 Sol verification, risk threshold 2, and at most 20
  claim cards per extraction.
- Luna is not the production verifier. The planned high-leverage production
  change is to route only count-bearing multi-cohort/large-count ambiguities
  **after** extraction, figure, and recovery layers have merged. That post-layer
  route has not yet been implemented or benchmarked.

## Limitations and next experiment

The fixed set is deliberately enriched for high-carrier, difficult papers and
is not representative of the full reviewer backlog. BRCA2 reference quality is
not equivalent to manual cardiac gold. Conditional MAE is low only among
supplied counts; count recall remains low. The next valid experiment is a
prospective, post-layer failure-routing run on a broader frozen cohort with
manual collaborator adjudication, reporting coverage, conditional MAE, recall,
per-gene strata, disagreement rate, route rate, latency, and token cost. Do not
replace the canonical production headline until that run passes its predefined
gate.
