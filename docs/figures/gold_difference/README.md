# Gold difference figure (companion view)

The canonical per-protocol-change figure is the stratified phenotype-count
recovery figure in
[`../evaluated_phenotype_counts/`](../evaluated_phenotype_counts/) (recipe:
`scripts/build_stratified_phenotype_count_recovery.py`, regenerated by
`run_eval.py score` after every scored candidate arm). This directory holds its
companion difference view: the same evaluation drawn as automated minus
reference for one locked run, over **every** gold row rather than only the rows
that received a count, with the frozen baseline arm on the identical rows.

## What is plotted

- One panel per count measure (carriers, affected individuals, unaffected
  individuals). Each gold row with an asserted value for the measure is one
  observation at (reference count, automated minus reference), both on
  square-root scales so single-carrier rows and 100-carrier rows share a panel.
- **Blue filled markers**: the automated extraction supplied an integer. On
  the zero line they are exact; above it over-counts; below it under-counts.
- **Coral outlined markers**: the variant was matched but no count was
  supplied. It is evaluated as 0, so the marker sits on the dotted lower
  boundary `difference = −reference`.
- **Grey dashed markers**: the gold variant was never found (identity miss),
  also evaluated as 0 and also on the boundary. Where misses and abstentions
  share a coordinate the marker is split into wedges by status.
- Marker area is the number of gold rows at the coordinate. The coral dashed
  line is the mean difference (bias); the grey dotted lines are the empirical
  2.5th and 97.5th percentiles of the difference.
- The stats under each panel give the denominator, identity coverage, count
  supply, exact fraction (with the share that is exact only because a gold
  zero met a scored zero), bias, end-to-end MAE, conditional MAE on supplied
  rows, the empirical limits and RMSE.

This is the end-to-end error definition preregistered for the secondary count
endpoint (`benchmarks/codex_paper_eval/secondary_count_endpoint.py`, carriers)
applied to all three measures. The script checks that its rows reproduce the
locked `report.json` (TP/FN, supplied counts, conditional MAE) and, when a
`compare` JSON is present, the registered end-to-end MAE and coverage exactly.

## Paired arms

When the run is the candidate arm of a mixed-gold tranche, the frozen baseline
arm is discovered from the tranche's consumption log and drawn above the
candidate on the identical gold rows. A strip under both rows gives the paired
deltas per measure (end-to-end MAE, supplied and exact rows, rows that got
better or worse, coverage on matched rows) and the identity recall/precision
deltas; when `run_eval.py compare` has run, its decision and one-sided
bootstrap bounds are printed too. Baseline before candidate, top to bottom, so
the page reads before, after, what changed.

## Files

Copies here are named by run id; the authoritative per-run copies live in
`benchmarks/codex_paper_eval/runs/<run>/figures/`.

- `<run_id>.svg` / `.png` / `.pdf` — the figure (editable SVG is primary).
- `data/<run_id>.csv` — one row per gold row and measure: reference count,
  raw and evaluated automated count, status, difference, source layer.
- `data/<run_id>.json` — metrics per arm and measure, paired deltas, the
  comparison decision, lock digests and the figure contract.

## Regenerate

```bash
# any locked run (the baseline arm is discovered for a candidate)
.venv/bin/python scripts/build_gold_difference_figure.py \
  --run-dir benchmarks/codex_paper_eval/runs/<run> \
  --copy-to docs/figures/gold_difference

# explicit pairing with the registered comparison
.venv/bin/python scripts/build_gold_difference_figure.py \
  --run-dir <candidate-run> --baseline-run-dir <baseline-run> \
  --comparison-json <candidate-run>/compare_discovery_with_secondary.json
```

`run_eval.py score` renders the figure for every scored run and
`run_eval.py compare` re-renders the candidate with the registered bounds, so
the per-run copies are refreshed without manual steps; only the `docs/figures`
copies need `--copy-to`. The discipline is recorded in
`docs/PROTOCOL_CHANGELOG.md`.
