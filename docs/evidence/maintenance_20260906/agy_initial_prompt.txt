### README.md
1: # GeneVariantFetcher (GVF)
2:
3: [![Python 3.11+](https://img.shields.io/badge/python-3.11+-blue.svg)](https://www.python.org/downloads/)
4: [![License: MIT](https://img.shields.io/badge/License-MIT-green.svg)](LICENSE)
5: [![Version](https://img.shields.io/badge/version-2.1.0-orange.svg)](CHANGELOG.md)
6:
7: Builds an auditable evidence database from gene-focused biomedical literature,
8: designed to run **autonomously at scale** — hundreds of genes and hundreds of
9: thousands of papers — with automated quality gates, not human review, as the
10: primary control.
11:
12: ## What GVF Does
13:
14: Given a gene, GVF discovers relevant papers, downloads full text and
15: supplements, extracts variants and carrier/count evidence with an LLM-backed
16: pipeline, and writes a queryable SQLite database with per-fact provenance so
17: every extracted count is auditable back to its source table, row, and quote.
18:
19: The design target is unattended operation across many genes: automated source
20: QC, acceptance gates, count guards, non-regression checks, and per-fact
21: provenance decide what to trust, so runs scale without a human in the per-paper
22: loop. Human adjudication is an **exception-only escape hatch** for the rare
23: marginal case — routed through
24: [Variant_Browser](docs/VARIANT_BROWSER_INTEGRATION.md), off the per-paper and
25: per-run critical path, never a required step. A per-fact **trust gate** sorts
26: every extracted fact into a **trusted** or **quarantine** tier using gold-free
27: structural checks (`pipeline/trust_gate.py`, default-on in `gvf-run`;
28: `scripts/trust_report.py` inspects the tiers). Its within-paper outlier rule is
29: a triage fallback: an explicitly labelled
30: per-variant count read by the deterministic table parser remains trusted, while
31: prose-derived, model-authored, and unlabelled outliers remain quarantined. The
32: optional source-grounded
33: final-check composer (`pipeline/paper_final_check_gate.py`) adds exact
34: model-found contradictions on top, and is currently parked — see
35: [`docs/EXTRACTION_CONTRACT.md`](docs/EXTRACTION_CONTRACT.md). The comparison scorer
36: now defaults to the trusted field projection while preserving raw counts and
37: variant identity; moving the remaining report/publish consumers and calibrating
38: the gate per gene class are still in progress.
39:
40: The current production entry point is:
41:
42: ```bash
43: gvf gvf-run <GENE> --email brett.kroncke@gmail.com --output ./results [--disease "<phenotype>"]
44: ```
45:
46: Source recovery, including paywall and supplement acquisition, runs by default.
47: Pass `--no-source-recovery` only for a fast PMC/free-text-only pass or a
48: controlled measurement run.
49:
50: ## Scope and Intended Use
51:
52: - **Operating model:** unattended, high-throughput extraction across many genes
53:   and hundreds of thousands of papers. Automated quality gates are the primary
54:   control; human adjudication is an exception-only escape hatch for the rare
55:   marginal case, not a per-record or per-run step.
56: - **Research use only.** GVF is not a patient-facing or clinical-decision
57:   system. Do not treat extracted variants, carrier counts, or classifications as
58:   clinical-grade.
59: - **Validation surface:** metrics are strongest on the four cardiac gold genes
60:   (KCNH2, KCNQ1, SCN5A, RYR2), which are in-distribution from repeated tuning.
61:   Generalization to other gene classes — e.g. BRCA1/BRCA2, whose truncating and
62:   case-control evidence differs structurally from cardiac missense — and
63:   arbitrary-gene cold start are exercised separately by
64:   [`benchmarks/cold_start_eval/`](benchmarks/cold_start_eval/README.md); report
65:   cardiac-gold, generalization, and cold-start numbers distinctly.

183: ## Pipeline Shape
184:
185: GVF's default workflow is:
186:
187: 1. Discover PMIDs from PubMind and PubMed (and Europe PMC when `USE_EUROPEPMC=1`).
188: 2. Fetch abstracts and apply Tier 1/Tier 2 relevance filtering.
189: 3. Download full text and supplements from PMC, publisher APIs, Unpaywall, and
190:    authenticated recovery routes when configured.
191: 4. Reuse or update the local source corpus under `corpus/`.
192: 5. Extract variants, carrier counts, phenotypes, provenance, and evidence.
193: 6. Migrate extraction JSON to SQLite.
194: 7. Run DB-observed recovery layers and the default-on per-fact trust gate. Its
195:    within-paper median rule yields to an explicitly labelled per-variant cell
196:    from the deterministic table parser, but still quarantines prose-derived,
197:    model-authored, and unlabelled outliers.
198: 8. Optionally run the `azure_ai/gpt-5.6-sol`/`xhigh` final per-paper sniff test
199:    (Step 3.8). **Parked — default off since 2026-07-26**; the cost and latency of
200:    an `@xhigh` call per paper were not justified by its measured effect on a step
201:    that only records findings. Revive with `PAPER_FINAL_CHECK_ENABLED=1` together
202:    with `PAPER_FINAL_CHECK_GATE_ENABLED=1`.
203: 9. Compose high-severity, source-quoted objective contradictions (wrong column,
204:    cohort total, population count, arithmetic or phenotype contradiction, wrong
205:    gene, or a count the source credits to another publication) into the trusted
206:    count-field projection (Step 3.9) — **parked with Step 3.8**. When enabled,
207:    weak/absent-support findings remain advisory, raw counts and variant
208:    identities remain auditable, and grounded completeness gaps make run
209:    acceptance nonzero and require replay.
210: 10. Produce optional recall scoring and report handoff artifacts.
211:

146: ### What This Does
147:
148: 1. **Discovers papers** — Searches PubMind and PubMed for KCNH2-related literature
149: 2. **Downloads full-text** — Retrieves papers from PMC and publisher APIs
150: 3. **Extracts variants** — Uses the configured LLM provider to identify genetic variants and patient data
151: 4. **Aggregates results** — Combines findings across papers
152: 5. **Creates database** — Migrates everything to a queryable SQLite database

237:         WHERE clinical_significance = 'pathogenic';
238:
239: # Get penetrance data
240: sqlite> SELECT v.protein_notation, p.total_carriers_observed, p.affected_count
241:         FROM variants v
242:         JOIN penetrance_data p ON v.variant_id = p.variant_id
243:         ORDER BY p.total_carriers_observed DESC
244:         LIMIT 10;
245: ```
246:
247: ## PMC-Only Mode (No API Keys)
248:
249: If you don't have publisher API keys, GVF still works using only PubMed Central:
250:
251: ```bash
252: # Works without publisher keys; skips live paywall recovery
253: gvf gvf-run KCNH2 --email brett.kroncke@gmail.com --output ./results --no-source-recovery
254: ```
255:
256: **Limitations:**
257: - Only ~30% of papers have PMC full-text available
258: - Supplemental materials may be limited
259: - Some high-value papers behind paywalls will be skipped
260:
261: For comprehensive coverage, obtain at least Elsevier and Springer keys (both free for researchers).

1: # GeneVariantFetcher — API Keys Guide
2:
3: How to obtain API keys for each service GVF uses, and what works without them.
4:
5: ## Quick Reference
6:
7: | API | Required? | Free? | Coverage Impact |
8: |-----|-----------|-------|-----------------|
9: | **LLM provider** | ✅ Yes | Varies | Anthropic, OpenAI, or Azure AI is required for extraction |
10: | **Anthropic** | One LLM option | No (pay-per-use) | Claude extraction and vision-capable tiers |
11: | **OpenAI** | One LLM option | No (pay-per-use) | OpenAI extraction tiers |
12: | **Azure AI** | One LLM option | Varies | Azure-hosted model deployments |
13: | **NCBI (Email)** | ✅ Yes | Yes | Required for PubMed |
14: | **NCBI API Key** | Optional | Yes | 3x faster rate limits |
15: | **Elsevier API key** | Optional | Yes | Metadata/API access for ScienceDirect |
16: | **Elsevier Insttoken** | Recommended | Institutional | Highest-leverage unlock for subscription full text |
17: | **Springer** | Optional | Yes | +10-15% paper coverage |
18: | **Wiley** | Optional | Yes (TDM) | +5-10% paper coverage |
19: | **PMC** | No key needed | Yes | ~30% of papers |
20:
21: ## Required: One LLM Provider Key
22:
23: **Purpose:** Powers LLM-based variant extraction (the core of GVF).
24: GVF accepts Anthropic, OpenAI, or Azure AI credentials through LiteLLM. A key
25: does not select its provider: `MODEL_PROVIDER` must match the credential. The
26: shipped default is `anthropic`.
27:
28: ### Common Options
29:
30: - Anthropic: create an API key in the Anthropic console and set `ANTHROPIC_API_KEY`.
31: - OpenAI: create an API key at [platform.openai.com](https://platform.openai.com/) and set `OPENAI_API_KEY`.
32: - Azure AI: configure your Azure AI Foundry endpoint and key with `AZURE_AI_API_KEY` and `AZURE_AI_API_BASE`.
33:
34: ### Configuration
35:
36: ```bash
37: # In your .env file
38: MODEL_PROVIDER=anthropic
39: ANTHROPIC_API_KEY=your-anthropic-key
40: # or:
41: # MODEL_PROVIDER=openai
42: # OPENAI_API_KEY=sk-your-key-here
43: # or:
44: # MODEL_PROVIDER=azure
45: # AZURE_AI_API_KEY=your-azure-ai-key
46: # AZURE_AI_API_BASE=https://your-resource.services.ai.azure.com
47:
48: # Or as environment variable
49: export ANTHROPIC_API_KEY=your-anthropic-key
50: ```
