== 3. Existing code precedent and the contract tension ==

- A dedicated LQTS-compendium parser (PMID 19841300) already emits affected = count for "Case" status rows with count_type "case" and unaffected = count for control rows; the guard accepts count_type "case". Gold agrees (67 exact affected there).
- The generic table router has a "closed case series" rule: when the ONLY count column header is a case-series people header ("Case count", "No. of patients", "Probands (n)") mapped to the affected role, it sets carriers = affected and declares count_type "case".
- The extraction contract says: "Never manufacture a phenotype partition. A diagnosis label, enrollment in a disease cohort, or absence of a reported diagnosis does not by itself prove affected or unaffected. Do not fill either field by ... setting affected = carriers." It ALSO says for frequency columns: "read the role from the noun: cases/patients/probands to affected, controls to unaffected".
- The phenotype guard (always on) clears affected when affected == carriers >= 2 and unaffected in {0, None} unless the affected count_type is "case"/"proband_count" or a phenotype-named column label exists. It clears affected == 0 unless sourced. The trust gate (Step 3.7) soft-quarantines a derived unaffected == 0 only in population/biobank/case-control/family-segregation designs.

== 4. My proposal (code-owned, deterministic, no LLM call) ==

New module pipeline/table_cohort_phenotype.py, run at the extraction success boundary right after the existing audited patient-row lane. For each deterministic-parser row that has a per-variant carrier count and NULL affected/unaffected, classify the SOURCE TABLE's cohort role from the caption (looked up in the source text when the parser stored only "Table N", including wrapped caption lines) plus the count-column header:

  EXCLUDE (no derivation) if caption/headers/column mention: family, families, kindred, pedigree, relative(s), segregation, cascade, carriers, genotype-positive, asymptomatic, symptomatic, affected, unaffected, penetrance, phenotype, ECG/QTc-style clinical columns, population, biobank, general population, exome/genome sequencing, gnomAD/ExAC/ESP/1000 Genomes/TOPMed, allele, frequency, MAF; or the table already has explicit affected/unaffected columns; or the row is a per-person clinical row (implicit one carrier per row); or the carrier count_type is not per_variant_carrier.
  CONTROL if caption or column names control(s), healthy, reference alleles, ostensibly healthy, normal individuals: emit unaffected = N, affected = 0 with count_type unaffected_control / control and a code-owned source stamp.
  CASE tier 1 (table-local evidence): the count column's noun is patients/probands/cases/index cases with a count word ("No. of patients", "Probands (n)"), OR the caption names the target disease (BrS, Brugada, LQT*, long QT, CPVT, the run's disease string) AND the column counts people (individuals/subjects/patients/probands/cases/"Number"/"COUNT"/"N"). Emit affected = N, leave unaffected NULL (the paper did not assess unaffected relatives; the lab's 0 is a convention the scorer treats as no-error against NULL), count_type "case", source stamp table_cohort_phenotype_v1, column_label = caption + column quote.
  CASE tier 2 (paper-level ascertainment, separately flagged so it can be disabled): caption has no cohort noun (case C above) but the title/abstract/methods state an unrelated-proband/patient disease cohort ("N unrelated patients/probands (with|referred for|diagnosed with) <disease>", "Probands With <Disease>"), the count column counts people, and no exclusion fires.
  Every derived value is distinguishable from a literal phenotype column: count_type, a code-owned source stamp that is scrubbed from model output, a phenotype_derivation audit block with the caption/column/ascertainment quotes, and a fact_provenance row.
