# GVF Protocol Changelog

**Per-iteration record of what changed in the extraction/scoring protocol.**
One row per protocol-affecting change (normally one merged PR). This is the
change-anchored ledger; two sibling docs give the other views:

- `docs/RECALL_HISTORY.md` — the metric-anchored trajectory (what moved recall/MAE).
- `docs/ARCHITECTURE.md` — the *current* end-to-end protocol (models, steps, guards).

**Discipline (do this every iteration):** when a PR changes the protocol
(prompts, extraction/table logic, guards, trust gate, scoring, discovery,
acquisition, or model routing), add a row at the **top of the table** below with
the date, PR, category, a one-line summary of the change, and its measured or
expected recall/MAE effect. If it moved a headline number, also add the detail to
`RECALL_HISTORY.md`; if it changed the current protocol shape, update
`ARCHITECTURE.md`. Never rewrite past rows — supersede with a new one.

Categories: `extract` (prompt/extraction/table logic), `trust` (guards, trust
gate, final check), `gold` (gold sync/scoring scope), `acquire` (source/
supplement acquisition), `discover` (search/priority), `infra` (harness, CI,
tooling), `docs`.

| 2026-07-27 | — | infra | **Absent genes stop scanning: the second half of the VariantFeatures index fix.** 88d486c made present genes indexed but left the miss path alone, so a gene *absent* from `variant_consequences` still fell through to `UPPER(<column>) = ?` and paid a full index scan of the 3.47M-row table — the case that matters most, because a novel gene is by definition absent (`docs/NEW_GENE_RUNBOOK.md`, [[feedback_no_gold_turnkey]]). `_gene_rows()` now recovers from an exact-match miss by consulting a cached census of the spellings the column actually stores and re-querying **those spellings by equality** (`column IN (...)`), instead of wrapping the column in `UPPER()`. Because the census enumerates every stored value, the `IN` list selects exactly the rows `UPPER(column) = ?` would have — and a gene with no stored spelling resolves to an **in-memory miss with no second query at all**. The census is built **lazily**, only on a miss, so the present-gene path is untouched. It walks the column with a recursive `MIN()` loose index scan — **one index seek per distinct value** (200 on the real slice) rather than the 3.47M-entry covering-index scan a plain `SELECT DISTINCT` plans (`0.034s` cold / `0.001s` warm versus `2.4–3.4s`); `_has_leading_index()` falls back to a single `SELECT DISTINCT` pass when no complete index leads with the column, because without one the walk would cost a full scan *per distinct value*. `lookup_variantfeatures_residue` also gains an `lru_cache` (it had none, and `pipeline/target_gene_specificity.py:206` calls it once per parsed protein position). Both caches, plus the census, are dropped by `clear_gene_metadata_cache()`. `_sqlite_upper()` folds ASCII only, matching SQLite's `upper()` rather than Python's Unicode-aware `str.upper()`, so the census keys stay equivalent to the predicate they replace. | **None — outputs verified identical to 88d486c** across all 200 stored `variant_consequences` symbols, all 12 builtins and 3 absent symbols (205 `get_gene_metadata` comparisons, 0 differences) plus 35 `lookup_variantfeatures_residue` pairs (0 differences). Pure cost win, **paired old/new in the same warm page-cache state**: absent gene `get_gene_metadata` **0.65s→0.002s** (~350x, and 20–24s→~0.002s measured in a cool state); mixed-case-only `C19ORF25` **0.647s→0.002s**; `known_gene_aliases()` **2.07s→0.089s** (23x — the 1.99s residual 88d486c left was 3 of the 12 builtins, `KCNE1`/`KCNE2`/`CACNA1C`, being absent). The dominant win is the per-position loop: 200 positions on an absent gene **60.5s→0.040s** (1528x; **332s** in the cool state), and **61.0s→0.008s** when positions recur. Present genes are unchanged (`TTN` 0.100s, `KCNH2` 0.009s, `LMNA` 0.001s); `TTN`'s repeat-position loop gains 5x from the new `lru_cache`. `tests/unit` with the sibling DB visible **56.0s→39.3s**, now statistically identical to the 40.9s it takes with no DB at all — the suite is no longer page-cache sensitive because no scans remain to be cold. **Accepted narrowing from 88d486c is retained, not dropped**: exact-casing-first still wins over a mixed-case twin (`C19ORF12` vs `C19orf12`), because unioning them would change real results and the constraint here was byte-identical semantics. Seven new tests in `tests/unit/test_gene_metadata.py` (14 total), each verified to fail against an injected regression — 11 regressions injected, 11 caught, including the `MAX()` all-NULL trap, an eager census, a first-spelling-only `IN` list, partial-index acceptance, both missing `cache_clear()` calls, and a Unicode case fold. The fixture now carries the real slice's indexes: without them the census took its unindexed branch, so the loose index scan production uses would have run in zero tests. No write to the sibling DB. |
| 2026-07-27 | — | infra | **VariantFeatures lookups stop defeating their own indexes.** Every gene-scoped query in `utils/gene_metadata.py` filtered on `UPPER(<column>) = ?`, which makes the column non-indexable: on the real 38 GB sibling slice `WHERE gene_symbol='KCNH2'` is **0.13s** (`SEARCH ... USING INDEX idx_consequences_gene`) versus **9.06s** for the `UPPER()` form (full index scan). Two such queries run per gene and `known_gene_aliases()` walks all 12 builtin genes, so a fresh GVF process paid minutes of scanning before doing useful work. All eight gene-scoped queries now route through `_gene_rows()`: indexed exact-match predicate first (`normalize_gene_symbol` already uppercases the parameter), `UPPER()` only as a fallback when the exact form finds nothing. The fallback is load-bearing, not defensive — `variant_consequences` holds **7,894 mixed-case rows** (`C19orf25`, `C19orf12`, `C19orf44`, HGNC's lowercase `orf`) and `C19ORF25`/`C19ORF44` have *zero* uppercase rows; `genes` (199 rows) and `transcripts` (299) are 100% uppercase, which is why those two lookups were never the bottleneck. Subtlety pinned by a new test: `SELECT MAX(...)` always returns one `(None,)` row, so an empty result cannot drive the fallback — the trigger is *a row of nothing but NULL*, and the obvious `if not rows` check would have silently dropped metadata for mixed-case genes with every test still green. A third test asserts on the executed SQL (`set_trace_callback`) so the *index-friendly* property is pinned, not just the result. | **None — outputs verified byte-identical** for all 12 builtin genes and the three `C19orf*` genes.
